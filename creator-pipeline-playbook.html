Before anyone pays

Reading the INSTARAW V2.0 offer

The models in the bundle (Wan 2.2, Z-Image Turbo, SDXL) and ComfyUI itself are free and open source. You'd be paying for their packaged workflows, custom nodes and support. That can be worth money for some teams, but the pitch has problems worth knowing first.

  • Numbers

    The scarcity counter doesn't add up. 777 minus 701 is 76, not the "82 left" it claims, and the same message also says "next 22 spots only." Countdown timers and "closed forever" are pressure tactics, not facts about supply. Digital files don't run out.

  • Payment

    Crypto can't be refunded. If you buy, use PayPal Goods & Services (not Friends & Family), which gives buyer protection. Ask for the refund policy in writing first.

  • Security

    "50+ proprietary Python nodes" is code that runs on your machine with full access to your files, browser data and saved logins. Malicious ComfyUI node packs have stolen credentials before. Don't install closed-source nodes from a Discord or Drive link on a computer that holds client or banking logins. Use a cloud GPU (RunPod, Vast.ai) or a separate machine.

  • "Lifetime"

    The offer promises "lifetime" access to a platform that will charge others monthly. Lifetime deals depend on the seller staying in business. There's no contract, so treat it as a one-time purchase of what's in the folder today.

  • Motion

    Motion control is "coming in V3." That's the feature your team actually asked about, and it isn't in what you'd buy today.

  • Consent

    The pitch leans on NSFW character LoRAs. Only train LoRAs on a fictional character you created or a person who gave written consent. Sexual deepfakes of real people are illegal in many countries, including under the US TAKE IT DOWN Act, and platforms ban accounts for them.

  • Free route

    Everything below gets you the same building blocks for free. ComfyUI's built-in templates already include Wan 2.2, Wan Animate and Z-Image workflows. What you'd give up is their batch-processing nodes and support.

How ComfyUI nodes work

ComfyUI is a visual programming tool. Each box (a node) is one Python function. Its sockets have types, such as MODEL, CLIP, VAE, CONDITIONING, LATENT and IMAGE, and you can only connect matching types. When you press Queue, ComfyUI runs the nodes in dependency order and skips any node whose inputs haven't changed since the last run.

  • Checkpoint: the base model (SDXL, Z-Image, Wan 2.2).
  • LoRA Loader: patches the model with your character or style. It sits between the checkpoint and the sampler.
  • KSampler: starts from noise and removes it step by step, guided by your prompt.
  • VAE Decode: turns the compressed "latent" result into real pixels.

Video workflows (Wan 2.2, Wan Animate) use the same idea with extra nodes for frames and reference video. Open Workflow → Browse Templates in ComfyUI to load working examples instead of building from scratch.

Python

Build your own node

A custom node is a folder inside ComfyUI/custom_nodes/ with an __init__.py. New nodes use ComfyUI's V3 schema: a class that describes its inputs and outputs, an execute method, and an entry point that registers it.

This example builds a Character Prompt node. It always puts your LoRA trigger word first, so nobody on the team forgets it.

ComfyUI/custom_nodes/team_nodes/__init__.py
from comfy_api.latest import ComfyExtension, io


class CharacterPrompt(io.ComfyNode):
    @classmethod
    def define_schema(cls) -> io.Schema:
        return io.Schema(
            node_id="TeamNodes_CharacterPrompt",
            display_name="Character Prompt",
            category="team_nodes",
            inputs=[
                io.String.Input("trigger", default="mychar"),
                io.Combo.Input("shot", options=["close-up portrait", "medium shot", "full body"]),
                io.String.Input("scene", multiline=True, default="walking through a sunlit market"),
            ],
            outputs=[io.String.Output()],
        )

    @classmethod
    def execute(cls, trigger, shot, scene) -> io.NodeOutput:
        prompt = f"{trigger}, {shot}, {scene.strip()}"
        return io.NodeOutput(prompt)


class TeamNodesExtension(ComfyExtension):
    async def get_node_list(self) -> list[type[io.ComfyNode]]:
        return [CharacterPrompt]


async def comfy_entrypoint() -> TeamNodesExtension:
    return TeamNodesExtension()
  1. Save the file, then restart ComfyUI. Nodes load only at startup.
  2. Double-click the canvas and search "Character Prompt". It appears under team_nodes.
  3. Wire its output into the text input of a CLIP Text Encode node (right-click the encoder → convert text to input if needed).
  4. Check the terminal window for errors if the node doesn't show up.

Working with images

Images arrive as a PyTorch tensor shaped [batch, height, width, channels] with values from 0 to 1. Use io.Image.Input("image") and return a tensor of the same shape.

Older node packs

Many existing packs use the V1 style: INPUT_TYPES, RETURN_TYPES, FUNCTION and NODE_CLASS_MAPPINGS. It still works, but new features go to V3 only.

Install other people's nodes through ComfyUI Manager from known GitHub repos, and skim the code before installing anything closed-source.

Weights

How LoRA works

A base model has billions of numbers (weights) that it learned during training. Retraining all of them to teach it one new character would need huge GPUs and produce a multi-gigabyte file.

LoRA (Low-Rank Adaptation) freezes the base model and trains a small "patch" instead. For each big weight grid, it learns two thin grids that multiply into a correction. The rank sets how thin they are: rank 16 or 32 is typical. The result is a file of tens to a few hundred megabytes that you load on top of the base model.

During training

  • Take one of your images and add random noise to it.
  • Ask the model to predict that noise, using the caption with your trigger word.
  • Measure the error and nudge only the LoRA patch.
  • Repeat a few thousand times.

When you use it

  • The LoRA only works with the base model it was trained on. An SDXL LoRA won't load on Wan 2.2.
  • Strength scales the patch: 0.6–1.0 is the usual range.
  • The trigger word from your captions calls up the character.
  • You can stack a character LoRA with a style LoRA at lower strengths.

Training

Train a character LoRA

Start with a still-image LoRA on Z-Image Turbo. It trains fastest and gives you consistent character photos to feed into video models. Move to a Wan 2.2 LoRA once the image version looks right.

1. Hardware

Plan on an NVIDIA GPU with 16 GB VRAM or more (24 GB is comfortable). Without one, rent a GPU on RunPod or Vast.ai for a few dollars a run, or use a hosted trainer such as fal.ai or RunComfy.

2. Build the dataset

  1. 15–30 images of the character. Variety beats volume: different angles, expressions, lighting, outfits and backgrounds.
  2. Use sharp images around 1024 px. Crop out other people, watermarks and text.
  3. Pick a trigger word that isn't a real word, such as zr4char.
  4. Put a .txt caption next to each image with the same filename. Start with the trigger, then describe the scene plainly:
dataset/zr4char/img_007.txt
zr4char, a woman in a green raincoat, three-quarter view, standing on a city street at dusk, soft streetlight, shallow depth of field

3. Install ai-toolkit

Ostris's ai-toolkit is free and has a web UI with a Z-Image Turbo preset. Follow the README for the exact PyTorch install for your GPU; the outline on Windows is:

5. Pick the best checkpoint

Don't assume the last save is best. Load several checkpoints in ComfyUI, generate the same 4 prompts with each (including a new outfit and a new angle), and keep the earliest one that holds the face while still following the prompt.

Moving to video: Wan 2.2 LoRAs

ai-toolkit and musubi-tuner both train Wan 2.2. The 14B model has two parts (high-noise and low-noise), so character LoRAs are usually trained for both. Guides suggest 20–50 images for text-to-video, rank 32, learning rate around 5e-5 on a 12 GB card. Expect a few hours per run. If you mainly use image-to-video, your Z-Image LoRA photos already give Wan a consistent starting frame, and you may not need a video LoRA at all.

Video API

Set up Seedance 2.5

Seedance 2.5 is ByteDance's closed video model. You can't download it or train LoRAs for it; you pay per render through an API. It does text-to-video and image-to-video at 1080p, up to 30 seconds, with generated dialogue, music and sound effects, plus reference-image inputs for consistent characters.

Option A: Comfy Cloud easiest

  1. Create an account at comfy.org (5 free runs, no card).
  2. Open a Seedance 2.5 template from the workflow library.
  3. Add your prompt or a start image and run.
  4. Buy credits or subscribe when the free runs are gone. Plans start at $20/month.

No GPU needed. Comfy says renders can be used commercially without a watermark.

Option B: Your own ComfyUI

  1. Update ComfyUI to the latest version.
  2. Sign in with your Comfy account inside ComfyUI and add credits. Seedance runs as a paid partner (API) node.
  3. Load the Seedance template, or search "Seedance" on the canvas.
  4. Mix it with local nodes, such as your LoRA image workflow feeding its start frame.

Community packs that call Seedance through third-party resellers also exist. Avoid them unless you trust the reseller with your API key and billing.

Save credits

Draft shots for free on Wan 2.2 locally, then render only the finals with Seedance.

Full pipeline

Putting it together

  1. Create the character. Design a fictional character, or get written consent from a real person.
  2. Train a Z-Image Turbo LoRA on 15–30 varied images.
  3. Generate key stills in ComfyUI with the LoRA and your Character Prompt node.
  4. Animate the stills: Wan 2.2 locally for drafts, Seedance 2.5 for finals, or Kling 3.0 / Wan Animate for motion swaps (see the motion swap brief).
  5. Score the results with the motion swap scorecard before choosing a paid tool.

If you still want INSTARAW after trying this, you'll know exactly which of their extras (batch nodes, prompt database, support) you're paying for.
