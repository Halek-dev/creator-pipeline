# Creator Pipeline

Our own ComfyUI setup for character images and video: a custom node pack, a batch runner, setup scripts and model profiles. Built on free, open-source parts (ComfyUI, Z-Image Turbo, Wan 2.2).

## What's here

| Path | What it does |
|---|---|
| `creator_nodes/` | Our ComfyUI node pack (appears under **creator** in the node menu) |
| `creator_nodes/prompt_library/` | JSON prompt libraries. Add a file here to add a library |
| `tools/batch_run.py` | Queues 10, 50, 100+ runs of a workflow and logs the outputs |
| `tools/download_models.py` | Downloads a model profile from `models.json` |
| `workflows/` | Test workflows in ComfyUI API format |
| `scripts/` | Setup and start scripts for Windows and Linux GPU servers |
| `tests/` | Unit tests for the node logic |

### Nodes

| Node | Inputs | Use |
|---|---|---|
| **Character Prompt** | trigger, shot, scene, style | Builds a prompt that always starts with the LoRA trigger word |
| **Prompt Library** | library, mode, seed | Fills a scene template. `random` picks by seed; `sequential` walks every combination without repeats |
| **Folder Image Loader** | folder, index | Loads one image by index from a folder. Index auto-increments and wraps, so queueing N runs walks the folder |
| **Reality Finish** | grain, vignette, warmth, lens fringe, JPEG quality, seed | Makes renders look like they came from a phone camera |

## Run it on a laptop (CPU only)

No GPU needed. Slow, but enough to test nodes and workflows.

```powershell
.\scripts\setup.ps1 -Cpu
.\scripts\start.ps1 -Cpu
```

Open http://127.0.0.1:8188. Then, in a second terminal:

```powershell
# Finish every image in ComfyUI\input\batch
.venv\Scripts\python tools\batch_run.py workflows\finish_folder.json --count 4 --step "Folder Image Loader.index=0"

# Optional: small test model (about 5 GB) for end-to-end image generation
.venv\Scripts\python tools\download_models.py cpu-test
.venv\Scripts\python tools\batch_run.py workflows\sd_turbo_character.json --count 3 --step "Prompt Library.seed=0" --random "Sampler.noise_seed"
```

Outputs land in `ComfyUI\output`. Each batch writes a log to `batch_runs\`.

## Motion swap (Wan Animate 2)

Reference image + driving video → the character performing that motion. Needs a 24 GB+ GPU; see [docs/MOTION_SWAP_RUNBOOK.md](docs/MOTION_SWAP_RUNBOOK.md) for the rented-GPU steps.

```bash
.venv/bin/python tools/batch_run.py workflows/wan_animate2.json --count 1
```

## Team app

`bash scripts/start.sh` also starts the team app on port 7860 and prints a public link for it. It is a hand-written front end ([app/web/static](app/web/static): one HTML file, one stylesheet, one script, no build step) over a small JSON API ([app/web/server.py](app/web/server.py), FastAPI) that drives the job engine in [app/jobs.py](app/jobs.py). Upload a reference image and a driving video, pick an engine, a character and scene preset, a quality tier (Fast / Standard / High), the clip length (1 to 3 passes of 81 frames, depending on the driving video), how many seeds, and optionally **Finish** (upscale ×2, double frame rate, sound). Press Render: the clip appears in the feed at once and shows its progress inside the card. The Library shows every clip with a contact sheet and face strip per seed, a compare player, downloads and a "Use these settings" button; every job's settings are stored on the volume (`ComfyUI/output/_jobs/`). Presets live in [app/presets.yaml](app/presets.yaml) and can be edited without touching code. Batch queues many clips from a CSV. Costs shows the month's render time, estimated pod bill and Seedance credits. Input rules: [docs/INPUT_GUIDE.md](docs/INPUT_GUIDE.md).

High tier and Finish need extra models once per volume: `bash scripts/setup.sh wan-animate-2-full finishing` (about 21 GB). Workflow variants are generated by [tools/build_workflows.py](tools/build_workflows.py) from the one base workflow.

**Engines.** *Wan Animate 2* (default; background from the scene text), *SCAIL-2* (swaps the character into the original video, keeps its background; `bash scripts/setup.sh scail2`, [tools/build_scail.py](tools/build_scail.py)), and *Seedance 2.5* (ByteDance's paid model through ComfyUI's API node, no GPU; needs `COMFY_API_KEY`; [tools/build_seedance.py](tools/build_seedance.py)). The **Describe** button fills the background text from the reference image or the driving video with Claude (needs `ANTHROPIC_API_KEY`).

Put a password on the public link with `APP_PASSWORD` (the browser asks for it; user `team`). For the people who only use the app: [docs/TEAM_GUIDE.md](docs/TEAM_GUIDE.md). For whoever maintains it: [docs/UPDATING.md](docs/UPDATING.md) (pinned versions, update procedure), `tools/cost_report.py` and `tools/pod.py` (start/stop the RunPod pod from a laptop with `RUNPOD_API_KEY`).

```bash
.venv/bin/python app/web/server.py     # run the app on its own (ComfyUI must be up); API at /api/*
```

## Batch runner

Address any input as `"<node title>.<input>"` (titles are the `_meta.title` values in the API workflow).

| Flag | Meaning |
|---|---|
| `--count N` | Number of runs |
| `--set KEY=VALUE` | Same value every run |
| `--step KEY=START` | START, START+1, ... per run |
| `--random KEY` | New random seed per run |
| `--jobs file.jsonl` | One JSON object of overrides per line, one run per line |
| `--dry-run` | Show the runs without queueing |

To batch a workflow you built in the UI: **Workflow → Export (API)**, save it in `workflows/`, then run it with the flags above.

## Rules for the team

- Only train LoRAs on characters we created or on people who gave written consent.
- Label AI-generated posts where the platform requires it (Instagram and TikTok both do).
- Only install third-party custom nodes from known GitHub repos, and read the code first.
